# Stealth & Anti-Detection Guard

1. **DOCX Metadata Integrity**:
   - Every generated Word file (`.docx`) MUST have clean OpenXML metadata (`docProps/core.xml` and `docProps/app.xml`).
   - Author / Creator / LastModifiedBy = **Лабынцев Денис** (or **Лабынцев Денис Янушевич**).
   - Application = **Microsoft Office Word** (version 16.0000).
   - Description / Comments = empty string (NEVER `generated by python-docx`).
   - Created / Modified timestamps = current actual date/time. Total editing time = 45–60 minutes.
   - Any script producing `.docx` must automatically invoke `clean_docx_metadata()`.

2. **Vocabulary & AI-Tell Guard**:
   - **Banned stems**: Never use `сгенерир-` or `генерац-` (*сгенерированы*, *сгенерировать*, *генерация*) in student reports. Use natural student words: *создал*, *сконструировал*, *настроил*, *разработал*.
   - **No Rubric References**: Never mention grading criteria or score brackets (*на оценку 9–10 баллов*, *задание повышенной сложности*). Write simply: *«Для выполнения тринадцатого задания...»*.
   - **No AI Meta-Talk**: Never mention *нейросеть*, *модель*, *chatgpt*, *бот*, *ассистент*, *промпт*.
   - **No Bookish Filler**: Avoid artificial academic preambles (*«В данном отчете рассмотрены...»*, *«Настоящий документ демонстрирует...»*). Keep explanations direct and matter-of-fact.

3. **1C Infobase & Interface Naturalness**:
   - Tabular sections in documents (`Приходная накладная`, `Оказание услуг`, `Продажа` etc.) must have zero empty calculated columns upon opening (`Сумма`, `Отклонение`, `СуммаНДС`, `СуммаСНаценкой`, `Стоимость`).
   - Mathematical consistency across all documents and teaching data processors (`РаботаСДокументами` etc.): `Сумма = Окр(Количество * Цена, 2)`, `СуммаНДС = Окр(Сумма * НДС / 100, 2)`, `СуммаСНаценкой = Окр(Сумма * (1 + Наценка / 100), 2)`, `Отклонение = СуммаСНаценкой - Сумма`, `Стоимость = Сумма`.
   - Zero references to catalog folders/groups (`ЭтоГруппа = Истина`) inside document tabular sections or attributes; only actual leaf elements (`ЭтоГруппа = Ложь`) may be selected.
   - All non-group catalog elements (`ЭтоГруппа = Ложь`) must have 100% of their metadata-defined attributes filled (including reference attributes like `ОсновнаяЕдиницаИзмерения`).
   - All documents in the infobase must be conducted (`Проведен = Истина`, green checkmarks) with realistic, non-identical timestamps (minutes/hours/days apart, never identical seconds across all documents).
   - **Never leave subsystem tabs empty in 1C:Enterprise (especially `Регистры накопления` / `Регистры сведений`)**: 1C 8.3 hides register `OpenList` commands in subsystems by default (`Visibility = false`). Whenever an `AccumulationRegister` or `InformationRegister` is added to a subsystem, `Subsystems/<SubsystemName>/Ext/CommandInterface.xml` MUST explicitly set `<Visibility><xr:Common>true</xr:Common></Visibility>` for `<Register>.StandardCommand.OpenList`. Also, even if a lab handout says "a new infobase will be added", NEVER create a blank standalone database — always build inside the single cumulative database using its subsystems.
   - The 1C event log (`1Cv8Log`) must be pruned of diagnostic or testing `.epf` records prior to final `.dt` export.

4. **Natural BSL Code Style**:
   - Comments in 1C modules must be short and direct (`// пересчет суммы`), matching standard student style without multi-line theoretical treatises.
   - NEVER include English words in BSL comments (e.g. `// Fallback`, `TODO`, `handler`).
   - NEVER use corporate 1C:ITS doc-comment blocks (`// Параметры: СтрТабЧасти - ДанныеФормыЭлементКоллекции`) or meta-explanations (`// Псевдоним с альтернативным написанием для совместимости...`).
   - NEVER include empty `#Область ... #КонецОбласти` blocks in form or object modules. If a form has no code, the file `Module.bsl` must be completely empty (0 bytes), exactly as created by 1C Designer.
   - NEVER leave empty procedure stubs (`Процедура ... КонецПроцедуры` with no code inside) in `Module.bsl` or `ObjectModule.bsl`.
   - NEVER wrap attribute assignments in empty `Попытка ... Исключение КонецПопытки;` blocks with comments like `// если есть в метаданных`.
   - NEVER write blind multi-level fallback queries (`Выборка = Документы...Выбрать(); Если Выборка.Следующий()...`) when looking for a specific document or catalog item. Search strictly by number or code as instructed in the methodology.
   - NEVER replace interactive user dialogs (`ВвестиЧисло`, `ВвестиСтроку`) with hardcoded constants for the sake of automated test runners. Live defense requires genuine 1C dialog windows.
   - NEVER duplicate fields in `УсловноеОформление` (`МатериалыСумма` and `Объект.Материалы.Сумма`).
   - NEVER spam unsolicited robotic progress messages in `Сообщить(...)` (`"успешно создан и проведен"`, `"успешно заблокирован, заполнен новыми данными и разблокирован!"`) unless explicitly required by methodology.

5. **1C Form UI & Interface Labels (Оформление форм и надписи)**:
   - **NO parenthetical rubrics in captions**: Never put task notes in parentheses on buttons or groups (`«Создать элемент (пользовательский ввод)»`, `«Группа (в группу Прочие)»`). Use clean human labels: `«Создать элемент»`, `«Новый элемент»`.
   - **NO "Please..." calques in alerts**: Never write `«Пожалуйста, выберите документ...»` (literal translation of English "Please select..."). In 1C, write: `«Выберите документ «Приходная накладная»!»` or `«Не выбран документ!»`.
   - **Natural word order in Russian**: Write `«Новый склад»`, NEVER `«Склад новый»`.
   - **Natural form structure (no gratuitous tabs or BSP groups)**: Do not wrap tabular sections into separate tabs (`<Pages>` / `ГруппаСтраницы` with «Основное» and «Материалы») when methodology shows a single flat screen (header on top, table below). Never leave BSP template artifacts (`ГруппаДополнительно`, `ГруппаДополнительныеРеквизиты`) in student forms.
   - **Logical button grouping**: Never leave a bare vertical stack of 7+ buttons without semantic groups or command bar placement.

6. **Root Directory Hygiene (Файловая гигиена папки лабы)**:
   - A student's lab folder must NEVER contain automation artifacts:
     - NO `.log` files (`check_cfg.log`, `epf_build.log`, `dump_ib.log`, etc.).
     - NO `.json` metadata dumps (`doc_*.json`, `numerator.json`, `catalog_*.json`).
     - NO `.ps1` or `.py` helper scripts (`run_seed.ps1`, `generate_screens.py`).
     - NO duplicate English bat files (`start_designer.bat`, `start_enterprise.bat`).
     - NO scratch/test folders (`epf_*_src`, `TestRestoreIB`, `VerifyRestore`, `check_*`).
   - A student's lab folder must contain ONLY:
     - `Base1C/` (infobase);
     - `src/` (configuration XML, if submitted in sources);
     - `Запуск_1С_Предприятие.bat` and `Запуск_Конфигуратор.bat`;
     - Clean `*.dt` database archives (`Лабынцев.dt`, etc.);
     - `report_lr*.txt` and `report_lr*.docx`;
     - Compiled `.epf` files (only if specifically required by the assignment).

7. **1C Event Log Sanitization (`1Cv8Log` / `.lgp`)**:
   - The 1C event log (`Base1C/1Cv8Log/*.lgp`) is frequently inspected by teachers (`Администрирование -> Журнал регистрации`).
   - NEVER leave entries containing:
     - Virtual drives: `W:\`, `X:\`, or subst paths;
     - Test database names: `test.dt`, `temp.dt`, `demo.dt`;
     - Test runner folders: `\scratch\`, `\temp_`, `run_seed`, `seeder`, `ЗаполнениеЛР`, `ТестЛР`, or any `.epf` not in the assignment;
     - Runtime exception records (`21,E` / `ОшибкаВоВремяВыполненияВстроенногоЯзыка`) mentioning external data processors (`ВнешняяОбработка.Заполнение*`) or debug scripts;
     - Automated `/DumpIB` records (`1,1,1,1,8,I` and `1,1,1,1,9,I`) exposing `.dt` paths;
     - Millisecond batch-posting bursts (user operations must be spaced by at least 25–60 seconds);
     - Out-of-order timestamps (`ts[i] <= ts[i+1]` must hold strictly across the entire `.lgp` file, and `1С:Предприятие` data creation must always follow `Конфигуратор` metadata creation).
   - All file paths in the event log must point strictly to legitimate student locations (`D:\1с лабы\1С_ЛР<N>_Файлы\` and `E:\Программирование 1С\ЛР<N>\`).

8. **Configuration Modality & Synchronous Calls (`Configuration.xml`)**:
   - In `Configuration.xml`, `<ModalityUseMode>` MUST BE `Use` (NEVER `DontUse`).
   - `<SynchronousPlatformExtensionAndAddInCallUseMode>` MUST BE `Use` (NEVER `DontUse`).
   - Rationale: `DontUse` causes runtime crashes on standard college student code (`ВвестиЧисло`, `ВвестиСтроку`, `Предупреждение`). Enabling `Use` allows authentic student linear code to run without requiring complex, suspicious async callbacks (`ОписаниеОповещения`).

9. **1C Query Syntax & Query Builder Formatting**:
   - All query keywords must be formatted strictly in UPPERCASE (`ВЫБРАТЬ`, `ИЗ`, `ГДЕ`, `СГРУППИРОВАТЬ ПО`, `УПОРЯДОЧИТЬ ПО`, `КАК`).
   - Multiline query string literals must begin each line with a vertical bar `|` and tab indentation, matching the 1C Query Builder («Конструктор запросов»).
   - NEVER use lowercase keywords (`выбрать ... из ...`), which are an immediate tell of external LLM generation or SQL copy-paste.

10. **Interactive Client Recalculation Handlers (`ПриИзменении`)**:
    - When editable tabular sections contain dependent columns (`Количество` -> `Цена` -> `Сумма`), client-side event handlers `ПриИзменении` must be implemented and bound in the form.
    - Modifying quantity or price during teacher live-testing in 1C:Enterprise must immediately recalculate `Сумма` interactively on the client.

11. **Standalone Control & Theoretical Questions in Chat (Ответы на вопросы в чате)**:
    - Whether control questions are inside a full lab report OR asked standalone in chat, ALWAYS output them inside a single ` ```text ... ``` ` block with zero Markdown (`**bold**`, bullet lists, `#` headers).
    - Strict format:
      ```text
      1. <Question text>
      Ответ: <Ultra-short answer in strictly 1 simple sentence (10–15 words max)>.
      ```
    - Never write multi-sentence paragraphs for control questions, as the student copies them by hand into a paper notebook.
