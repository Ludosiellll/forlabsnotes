# MCP-кандидаты для работы Gemini с 1С

## Summary

В проекте уже описаны два разных 1С-инструмента: `1c-litecode` для поиска по XML/BSL-выгрузке и `1C MCP Toolkit (Native)` для запросов к работающей базе через `.epf`. Это не одно и то же, и найденный в интернете `1C MCP Toolkit` может дублировать уже описанный Native Toolkit. До проверки фактического подключения новый сервер добавлять рано.

## Что уже есть в проекте

| Инструмент | Для чего предназначен | Что проверено |
| --- | --- | --- |
| `1c-litecode` | Индексирует отчёт конфигурации, XML-дамп, BSL-модули и формы; ищет по структуре метаданных и коду | README сервера описывает формат входа `metadata/` и `code/`. Однако `antigravity.yaml` запускает `lite/test_mcp.py`, а этот файл — тестовый HTTP/SSE-клиент для `localhost:6005`, не сам MCP-сервер |
| `1C MCP Toolkit (Native)` | Через внешнюю обработку предоставляет запросы к живой базе, метаданные, журнал регистрации и выполнение BSL | Навык `tools/1c-syntax-mcp/skills/1cskills/SKILL.md` записывает endpoint `http://127.0.0.1:6003/mcp` и восемь инструментов. 2026-09-23 порт 6003 не слушал; это говорит только о том, что сервер в тот момент не был поднят |
| `1c-batch` | Выгрузка/загрузка конфигураций в XML, сборка/разборка `.epf`, запуск Конфигуратора и Предприятия | Операции документированы в локальном навыке `1c-batch` |

В стандартном глобальном конфиге Antigravity были только `memory`, `codebase-memory` и `supabase`; проектного `.agents/mcp_config.json` не было. Официальные места подключения Antigravity — `%USERPROFILE%\.gemini\config\mcp_config.json` и `<workspace>\.agents\mcp_config.json` ([документация](https://antigravity.google/docs/mcp?tab=ide)). `antigravity.yaml` сам по себе не подтверждает, что эти MCP загружены.

## XML и EPF — разные слои

- `.epf`-сервер получает структуру и данные из работающей информационной базы. Это помогает проверять фактическую конфигурацию и результаты выполнения, но не означает, что он напрямую читает произвольные XML-файлы на диске.
- XML/BSL-файлы читает файловый поиск, `1c-litecode` или другой индексатор исходников. XML можно получить из базы отдельной операцией `ibcmd config export` или пакетными скриптами.
- Для BSL и XML правки полезно сочетать чтение исходников со статическими проверками, сборкой и проверкой результата в базе. Runtime MCP не заменяет весь этот цикл.

## Внешние кандидаты

| MCP | Что добавляет | Ограничения для текущего проекта |
| --- | --- | --- |
| [1C MCP Toolkit](https://github.com/manilotw/1c-mcp-toolkit) | Live-запросы, чтение метаданных и журнала регистрации через `.epf` | README указывает 8.3.25 и endpoint на порту 6003, набор инструментов совпадает с локальной записью `1C MCP Toolkit (Native)`. Сначала выяснить, является ли локальная обработка той же реализацией; иначе это, вероятно, дубль. `execute_code` исполняет BSL, его следует держать под подтверждением и проверять на копии базы |
| [1C: Platform Tools MCP](https://yellow-hammer.github.io/vscode-1c-platform-tools/mcp/) | Команды сборки/загрузки, профили запуска и тесты с выводом результата | Требует расширения Platform Tools и проекта с `packagedef`; интеграция с Antigravity прямо не заявлена |
| [METR — MCP 1C Test Runner](https://github.com/alkoleft/mcp-onec-test-runner) | Сборка и запуск тестов YaXUnit из MCP | Полезен при наличии тестового набора; требует JDK 17+, YaXUnit и настройки `source-set` |
| [EDT-MCP](https://github.com/DitriXNew/EDT-MCP) | Работа с проектом EDT, проверками, метаданными и исходниками | Требует перехода на EDT и не является лёгкой надстройкой над текущим XML/Designer-процессом |

## Рекомендация

1. Попросить Gemini сначала показать MCP-инструменты, реально доступные в текущем сеансе, отдельно указав: поиск по XML/BSL, доступ к live-базе, синтаксис/валидация, сборка и тесты.
2. Сверить список с локальными записями `1c-litecode`, `1C MCP Toolkit (Native)` и `1c-batch`; не добавлять повторно то, что уже работает.
3. Если XML/BSL-контекст не подключён, чинить подключение `1c-litecode` к корректному MCP endpoint и его входному каталогу, а не подключать ещё один runtime Toolkit.
4. Если остаётся конкретный пробел в сборке или тестировании, отдельно оценивать Platform Tools или METR с проверкой совместимости и проекта-копии.

Необходимость дообучения не следует из найденных записей: сначала стоит проверить доступность и правильное назначение уже имеющихся инструментов. Внешние сведения сверены по документации и репозиториям авторов на 2026-09-23; их версии и совместимость могут меняться.
